# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMは講座固有の定義を知らず、「基礎／応用／発展という難易度分けが一般的」という推測で答えた。エージェントは search_glossary で用語集を確認してから、基礎＝講義内容の確認、実装＝自分でコードを書く、発展＝調査や試行で、どれか1つに取り組めば完了（原則として採点はなし）と正確に答えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」に対して、search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) の2回。用語を1つずつ検索していた。
- 1つの質問での LLM 呼び出し回数（`requests`）：2
- 追加したツールと、docstring に書いた説明：make_quiz(lecture: int)。docstring には「ある回の復習のための確認問題を求められたときに使う。引数 lecture には問題を作りたい回の番号（1始まりの整数）を入れる。用語集からその回の用語を1つ選び、問題文と答え（定義）を JSON で返す」と書いた。用語が無い回（例：0）を指定された場合は、その旨のメッセージを返すようにした。`--trace "第2回の内容から確認問題を1問出して"` で make_quiz({'lecture': 2}) が呼ばれ、「事前学習」の問題が出題されることを確認した。

## 宿題

- 取り組んだレベル：基礎・実装・発展（(a) ADK 書き直し、(b) のプロンプト比較も実施）

### 基礎

- やったこと：app/tools.py の search_glossary の docstring を「query には調べたい用語を1つだけ入れる」から「query には調べたい用語をまとめて入れる」に書き換え、同じ質問「LoRAとQLoRAの違いは？」を `--trace` 付きで実行して、変更前と比べた（実験後に docstring は元に戻した）。
- 結果：変更前は search_glossary が2回（'LoRA'／'QLoRA'）呼ばれたが、変更後は search_glossary({'query': 'LoRA QLoRA'}) の1回だけになった。回答の内容はほぼ同じだった。一方で、まとめて検索すると検索側でヒットする用語が絞られ、用語によっては取りこぼす可能性もあると感じた。
- 気づき・疑問：docstring は単なる説明文ではなく、モデルの行動（ツールを何回、どんな引数で呼ぶか）を決める指示として働くことが分かった。ツールの説明の書き方そのものが、エージェントのふるまいの設計なのだと思った。

### 実装

- やったこと：学習内容を learning_log フォルダに保存するツール save_learning_log(topic, content) を app/tools.py に作り、app/agent.py で requires_approval=True を付けて登録した。エージェントの output_type に DeferredToolRequests を加え、CLI 側に承認ループを実装した（承認待ちの呼び出しごとに「実行してよいですか？ [y/N]」と聞き、DeferredToolResults と message_history を渡して再実行する）。INSTRUCTIONS にも「記録を求められたら save_learning_log を使う（承認が必要）」の1行を足した。
- 結果：「今日学んだことを学習ログに保存して」と頼むと、実行が承認待ちで止まり、承認すると learning_log/20261108-041529.md が作られて内容も正しく保存された。拒否（N）するとファイルは作られず、エージェントが「保存はキャンセルされた」と正しく伝えた。既存のテストは15件すべてパスした。
- 気づき・疑問：承認付きツールでは「モデルがツールを呼ぶ」ことと「実際に実行される」ことが分かれていて、その間の状態（DeferredToolRequests）をプログラム側で受け取って処理する設計になっているのが面白かった。output_type に加え忘れるとエラーになる点も含め、フレームワークが「危険な操作は止まれる場所を作る」ことを強制する形になっていると感じた。

### 発展

- (a) やったこと：adk_agent/glossary_agent/ に root_agent を作り、Pydantic AI 版とまったく同じ INSTRUCTIONS と3つのツール（search_glossary / get_lecture_summary / make_quiz）を Google ADK の Agent に渡して、`adk run` で動かした。
- (a) 結果・比べたこと：書き方は、Pydantic AI 版が「Agent を作って tool_plain で1つずつ登録し、実行ループ（run_sync）や trace 表示は自分の CLI で用意する」のに対し、ADK 版は root_agent の宣言だけで、対話実行（REPL）までフレームワークが用意してくれた。回答は「3レベル」「LoRAとQLoRAの違い」ともに用語集に基づく正しい内容で、関係する回（第N回）の表示も付き、内容に実質的な差はなかった。
- (b) やったこと：コーディングエージェント Pi の公開リポジトリにあるシステムプロンプト生成コード（system-prompt.ts）を読み、自分の INSTRUCTIONS と比べた（Pi 自体の実行は行っていない）。
- (b) 結果・比べたこと：Pi のプロンプトはコードで動的に組み立てられていて、役割宣言（「pi の中で動くコーディングアシスタント」）、使えるツールの一覧、ツールごとのルール（「ファイル操作は bash で」「回答は簡潔に」「ファイルパスを明示」）、ドキュメントへの参照、プロジェクトの文脈ファイル、作業ディレクトリまで含む。自分の INSTRUCTIONS は7行で、担当領域の振る舞い（用語集を先に確認する、推測で断定しない、回の番号を示す、宿題の答えは書かない）だけを書き、ツール説明は docstring 側に寄せている。Pi は「確認を求めずにファイルやコマンドを操作する」エージェントなので操作の進め方と安全のルールが中心で、学習支援では正確さと教育上のルールが中心になる、という対比が見えた。
