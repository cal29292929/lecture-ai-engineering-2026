# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMは講座固有の定義を知らず、「基礎／応用／発展という難易度分けが一般的」という推測で答えた。エージェントは search_glossary で用語集を確認してから、基礎＝講義内容の確認、実装＝自分でコードを書く、発展＝調査や試行で、どれか1つに取り組めば完了（原則として採点はなし）と正確に答えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」に対して、search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) の2回。用語を1つずつ検索していた。
- 1つの質問での LLM 呼び出し回数（`requests`）：2
- 追加したツールと、docstring に書いた説明：make_quiz(lecture: int)。docstring には「ある回の復習のための確認問題を求められたときに使う。引数 lecture には問題を作りたい回の番号（1始まりの整数）を入れる。用語集からその回の用語を1つ選び、問題文と答え（定義）を JSON で返す」と書いた。用語が無い回（例：0）を指定された場合は、その旨のメッセージを返すようにした。`--trace "第2回の内容から確認問題を1問出して"` で make_quiz({'lecture': 2}) が呼ばれ、「事前学習」の問題が出題されることを確認した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：app/tools.py の search_glossary の docstring を「query には調べたい用語を1つだけ入れる」から「query には調べたい用語をまとめて入れる」に書き換え、同じ質問「LoRAとQLoRAの違いは？」を `--trace` 付きで実行して、変更前と比べた（実験後に docstring は元に戻した）。
- 結果：変更前は search_glossary が2回（'LoRA'／'QLoRA'）呼ばれたが、変更後は search_glossary({'query': 'LoRA QLoRA'}) の1回だけになった。回答の内容はほぼ同じだった。一方で、まとめて検索すると検索側でヒットする用語が絞られ、用語によっては取りこぼす可能性もあると感じた。
- 気づき・疑問：docstring は単なる説明文ではなく、モデルの行動（ツールを何回、どんな引数で呼ぶか）を決める指示として働くことが分かった。ツールの説明の書き方そのものが、エージェントのふるまいの設計なのだと思った。
